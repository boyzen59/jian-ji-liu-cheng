# AI 初期定位模块

本模块在任何分镜、素材搜索、Remotion 或 HyperFrames 实装之前运行。目标是用最少追问锁定会改变成片方向的变量，不把用户拖进冗长表单。

## 对话规则

1. 先从当前请求、附件名、文稿、字幕和目录中提取答案，再提问。
2. 一轮只问 1–2 个最关键问题。用户回答后更新简报，再问下一缺口。
3. 不把内部阶段名、评分或覆盖率暴露给用户；用自然语言提问。
4. 模糊形容词必须落成可执行判断。例如“高级”要转成信息密度、材质、运动幅度、转场频率和禁用项。
5. 不询问视觉主题或强调色：固定使用 `Soft Signal / 亲密 · 温暖`。连续字幕只交外挂文件；需要外挂字幕样式参考时沿用固定橙色。
6. 用户说“你决定”时，基于平台、受众和素材做保守选择，把假设写进简报后继续。
7. 只有缺失信息会实质改变结构、事实、录音或交付时才阻塞；低风险缺省项不阻塞。

## 先自动提取

建立 `known / inferred / missing / conflict` 四栏：

- 项目名称与核心主题
- 视频目的：解释、说服、教学、纪录、评论、品牌、转化
- 目标观众与其已有认知
- 发布平台、横竖屏、分辨率、帧率、目标时长
- 核心命题：观众看完应记住的一句话
- 信息密度与叙事气质
- 文稿、锁定音频、口播视频、SRT、翻译是否存在
- 用户图片、视频、录屏、资料和参考片是否存在
- 真人是否出镜以及是否需要后补对口型
- 事实、隐私、版权、品牌和禁用内容边界
- 最终需要的交付物

相互冲突时不要猜。例如录音时长与 SRT 末尾不一致、中文正文与英文稿含义不同、用户要求 16:9 但平台是竖屏，都要明确指出冲突。

## 问题路由

只问 `missing` 或 `conflict` 中优先级最高的项。

### A. 定位

- 这支片最主要要让观众理解、相信或采取什么行动？
- 目标观众是谁？他们对主题已经知道多少？
- 如果只能留下一个结论，必须是哪一句？
- 这是事实解释、观点论证、课程、纪录，还是转化型内容？

通过标准：目的、观众、唯一主结论可写成明确句子。

### B. 发布和时间

- 发布到哪里？横竖屏、时长、分辨率和帧率是否已固定？
- 是否已有不能改动的录音或口播？若有，以哪个文件为准？
- 是否已有中文 SRT？字幕末尾和录音精确时长是否一致？

固定主交付为：2560×1440、16:9、60fps CFR、H.264/AVC High、yuv420p、Rec.709、MP4、无音频流、无烧录连续字幕。只有用户明确要求项目例外时才覆盖并记录批准来源；锁定录音存在时不得用估算文稿字数代替真实时长。

### C. 素材

- 先读取用户已核对的素材清单、清单顺序、锁定文案段 ID 与实际文件路径；已锁条目不得重新判断匹配关系、交换顺序或跨段借用。文件缺失、损坏或不可读时报告阻塞，不自行替换。
- manifest 标为 `archive_evidence` 或 `book_evidence` 的图片进入证据分屏，使用简中＋英文来源解释并禁止动态说理；普通/AI图片按清晰原图全屏处理。
- 当前已有哪几类素材：图片、视频、录屏、档案、图表、品牌、真人？
- 哪些素材必须出现，哪些只可参考，哪些禁止使用？
- 是否允许公开检索、AI 补图/补视频或程序化重建关系图？
- 资料是否涉及隐私、未公开数据、版权或必须保持原貌的证据？

通过标准：每类素材的可用性、来源和替代路径清楚。

### D. 叙事和人物

- 开场 15 秒内真人全屏与 HyperFrames 双侧说明如何建立信任？正文可左右择位并抬高的小窗是否有合格头肩裁切？
- 真人是同步收音、后补手势对口型，还是只做主持人锚点？
- 哪些位置必须由人建立信任：开头、章节开头、总结、结尾？
- 参考片中最想保留和最不想出现的分别是什么？

人物默认：完整连续语义段；只有总开头和实际最终结尾允许全屏。每章先出现全屏大字章节总览，随后到最终总结前只使用抬到 220px 字幕排除区之上的右下圆形小窗（2560×1440 默认直径约 360px）或撤下；最终全屏持续到最后一帧。说明动效逐镜比较 Remotion 与 HyperFrames，不固定引擎。

### E. 外挂字幕和双语解释文字

- 是否已有中英对照稿供双语解释图、标题和逻辑框架使用？
- 中英对照稿是否经过确认？专名、数字和单位是否已有术语表？
- 屏显可以忠实压缩到多大程度？编辑性总结是否需要逐条批准？

缺省：连续字幕不烧录，交独立 SRT/ASS；讲解中的标题、节点、箭头、数字、逻辑框架和 PPT 式文字必须中英结合、放大醒目，并先过文字门禁。2560×1440 底部固定保留 220px 字幕排除区；正文/卡片文字从 42–54px 起调，辅助文字不低于 32px。外挂字幕若需要样式参考，沿用 Soft Signal 橙色。

### F. 声音

- 人声是否已锁定？是否已有 BGM 或指定音乐气质？
- 是否有指定 AI 音乐平台，或允许从 YouTube Studio Audio Library 选择合规轻音乐？
- 平台是否有特定响度或广告规范？

缺省：人声为唯一主声轴；外部/AI 视频静音；BGM 优先原创 AI 轻音乐或 YouTube Studio Audio Library 合规曲目并自动 ducking。交付独立 voice/BGM/SFX/审片混音，最终视频母版无音频流。

### G. 参考与反参考

- 参考片中要借的是构图、节奏、运镜、文字，还是声音？
- 明确拒绝哪些质感：游戏音、霓虹、故障、卡片海、过度 PPT、快闪、手持抖动等？

不要把单个参考片的全部特征扩散到全片。把参考拆成“可迁移手法”和“禁止照搬外观”。

## Gate 判断

`READY` 必须满足：

- 有明确目的、受众、核心命题
- 有确定的时间基准或明确的临时时长
- 有文稿或可用于分镜的内容源
- 素材使用边界明确
- 平台、画幅、语言和交付清楚
- 重大事实/隐私/版权风险有处理原则

`READY_WITH_ASSUMPTIONS`：仅缺少 BGM、少量素材或次要参考，可写出低风险假设继续。

`BLOCKED`：缺少正文/锁定音频、存在未解决的事实冲突、用户必须选择的核心立场、或将造成大规模返工的画幅/语言冲突。
