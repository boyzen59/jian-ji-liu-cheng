# 动效文字执行手册与 Word 门禁

当前既有文字动效审阅全部视为通过。只有新增或改字的 Remotion、HyperFrames（用户有时称 HypeHouse）、图片/视频上方局部毛玻璃、历史资料来源区、Lottie、D3、Blender/Manim 合成文字，才进入增量 Word《动效文字执行手册》门禁。仅调整版式、字号、位置、材质或运动而不改字时不重审。

## 生成时机

1. 新增屏显或修改既有中英文后、实装前。
2. 用户修改正文、翻译、术语或 SRT 后。
3. 分镜改变并实际导致文字新增、删改或重新压缩后；纯版式变化不触发。
4. 终渲前若存在任何文字改动，再生成最终归档版。

文件名：

`动效文字执行手册_V{版本}_{YYYYMMDD-HHmmss}.docx`

项目目录中另保留稳定别名 `动效文字执行手册.docx`，便于用户打开最新版。可另保留兼容别名 `时间码与屏显文字审阅表.docx`。不得覆盖历史版本；复制或另存稳定别名时保留版本文件。

## 每行必须回答

- 什么时候出现：起止时间码、时长、章节、镜号/文字编号
- 出现在哪里：开场/结尾真人全屏双侧组件、抬高圆形人物小窗旁、清晰图片/视频上方的局部文字毛玻璃、历史资料标题/来源区、章节全屏大字总览、标题、图表、流程、节点和外挂字幕文件等
- 来源是什么：原文完整句和来源文件
- 实际显示什么：英文主文、中文标注或单语文案
- 做过什么编辑：原文直取、忠实压缩、编辑性总结
- 当前情况：保留、排版调整、建议修改、必须修改、待确认、已确认
- 改动类型：`unchanged_approved｜layout_only｜new｜changed`；只有 `new|changed` 进入门禁
- 问题是什么：超长、来不及读、语义偏移、术语不一致、数字/单位冲突、遮挡、证据来源不明等
- 建议怎么改及为什么
- 用户决定：保留原文、采用建议、自行改写、删除、待定
- 批准证据：批准版本、日期和用户决定来源；空白视为未批准

## 自动检查规则

- 时间码合法且 `end > start`。
- 最终视频不烧录连续字幕；SRT/ASS 单独审阅和交付。同一时间只允许一个主要双语解释文字组；标题/标签可并存但要注明层级。
- 英文和中文语义一致，不能新增因果、夸大程度或弱化限定词。
- 专名、数字、日期、单位与术语表一致。
- 阅读时间不足时优先拆组或改版式，不先改用户原文。
- 内容必须压缩时标为 `建议修改`；编辑性总结一律 `待确认`，除非用户已明确批准。
- 资料原文、法律/医疗/金融结论、引用和统计数字不得由系统静默改写。
- 仅位置、字号或换行变化归 `排版调整`，不冒充文字修改。

## 放行规则

- `必须修改` / `待确认`：硬阻塞 Remotion/HyperFrames 实装。
- `建议修改`：交用户判断；用户未决定前不把建议当成定稿。
- `保留` / `已确认` / `排版调整`：仅在用户批准版本已记录时可放行；系统自行填写“保留”不等于用户核对。
- 每次放行在项目状态写入版本、时间戳和用户决定来源。
- 实装时只能读取已放行版本；发现新问题回到本门禁，不在代码里偷偷改字。

## Word 文档结构

1. 标题、项目、版本、生成时间（含时区）、规格、源文件
2. 状态图例和放行规则
3. 逐条文字审阅表
4. 汇总：各状态数量、阻塞项列表、未确认术语
5. 用户签批区：版本、日期、结论和备注
